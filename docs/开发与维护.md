# 开发与维护

## 构建与检查

`python scripts/build.py` 生成 `dist/index.html` 和摘要。脚本缓存位于 `.cache/app.js`，不进入Git。`python scripts/check.py` 先构建再运行全部回归检查。Python与Node部分均无需下载依赖。

主代码在 `src/js/`，模板在 `src/template.html`，响应式样式在 `src/styles/`，配置与翻译在 `src/config/`。公共字体/品牌资源在 `assets/`，离线模块在 `vendor/`，许可只维护 `licenses/` 一份。

构建使用仓库相对路径，可从其他工作目录调用。HTML固定CRLF换行，与原Windows v3.10逐字节一致；`.gitattributes` 禁止Git改写它。修改源码后须重新构建，检查模板会确认发布文件同步。

需要Python 3.10+、Node.js 20+；本机Python为 `F:\anaconda3\python.exe`。可选GitHub检查模板使用Python 3.12、Node 22。

模板见 docs/ci-workflow.example.yml。当前GitHub连接不含写入工作流的权限，本次未启用远端自动运行。具有相应权限的维护者可将模板放入 .github/workflows/check.yml 后启用。模板仅申请仓库内容只读权限。

## 数据约定

- 冻结研究数据在 `data/research/`，更新需同步口径和统计基准。
- 行情快照在 `data/market/`，与研究部分分开。
- `tests/fixtures/` 仅保留解析器需要的真实响应，完整旧资料归档。
- 页面运行不需要账号、密码或访问令牌，不应将这些信息写入源码。

## 发布

1. 修改功能、`project.json`、页面版本和说明，运行 `python scripts/check.py`。
2. 运行 `python scripts/package_release.py`，生成包含离线HTML、许可和说明的ZIP。
3. 提交源码和 `dist/index.html`，创建版本标签。
4. 将ZIP作为GitHub Release附件上传，更新入口和SHA256，不再复制整套源码目录。

本次16个旧版本包保留原 `outputs/版本/` 层次；以后统一打包入口的ZIP直接以 `index.html` 为入口。历史资料包保留旧 `work/` 层次。

## 本次迁移

本机 `outputs/`、`work/` 留在磁盘并被忽略，原本地网页路径仍有效。新克隆仓库使用 `dist/index.html`。以后只维护新目录，旧文件不会自动随新源码更新。

未重写历史或删除旧标签，默认分支停止重复跟踪旧目录。完整克隆仍包含旧历史对象；如仅需最新内容，可使用 `git clone --depth 1`。历史网页从Releases取得，历史源码从标签取得。
